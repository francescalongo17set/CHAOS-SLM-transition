# 07 · Repo, branches, environments

## Branch model (C-16, P-06)

```
orchestrator/baselines          ← base: shared package + handbook + audit
  ├── orchestrator/baselines-kev-0.8b ← Kev pipeline (larger runs: -4b, -9b)
  ├── orchestrator/baselines-laya     ← Laya pipeline
  └── orchestrator/baselines-nimble   ← Nimble pipeline
```

Why `baselines-kev-0.8b` and not `baselines/kev` (C-27): git stores branches as paths; a branch `orchestrator/baselines` and a branch `orchestrator/baselines/kev` cannot coexist. If the owner prefers another naming scheme, ask.

**Order of work matters.** Everything shared must be merged into `orchestrator/baselines` **before** the pipeline branches start, otherwise three branches will invent three versions of the data loader and the log format.

| Stage | Branch | Content |
|---|---|---|
| 0 | `orchestrator/baselines` | Shared package: data loader, state serializer, question config loader, dispatcher with unit test, log writer and validator, evaluation script, token counter (reference tokenizer), audit script. Plus the handbook folder. |
| 1 | the three pipeline branches | Pipeline-specific code and notebooks only. Pull shared changes from the base branch, never fork them. |
| 2 | `orchestrator/baselines` | Merge results (run logs, reports) back; produce `comparison.md`. |

## Layout (approved, C-27)

```
orchestrator-baselines/
  handbook/                 # this folder
  plans/                    # P0..P4 plans
  common/                   # shared package (no model-specific imports)
    data.py  state.py  questions.py  dispatcher.py  logs.py  tokens.py  evaluate.py  report.py  compare.py
    questions.en.yaml       # question and option text (C-21)
    tests/                  # pytest; run from orchestrator-baselines/
  audit/                    # audit.py, token_lengths.py, audit_report.md
  requirements-common.txt   # pyyaml, tokenizers, huggingface_hub, pytest
  kev/    laya/    nimble/  # pipeline code, notebooks, requirements-*.txt
  runs/<pipeline>/<run_id>/ # <split>.jsonl + run.json + report.md + metrics.json
  reports/comparison.md
```

Rules:

- `common/` has **no** dependency on kev, laya, nimble, transformers or torch (only the standard library, `pyyaml`, and a tokenizer library for `tokens.py`). It must run on a laptop.
- Pipelines import `common/`, never the reverse.
- Large artefacts (model weights, caches) are never committed. Run logs are small JSONL files and are committed.
- Run logs are committed only after the shared validator passes.

## Environments (C-26: one per pipeline)

Upstream requirements differ and conflict:

| Pipeline | Python | Key packages (from the READMEs) |
|---|---|---|
| Kev | 3.12 or 3.13 (the repo pins 3.13; torch had no wheels for 3.14) | `uv`, torch, `flash-linear-attention` on CUDA for Qwen3.5 |
| Laya | 3.10+ | `pip install laya`; set `USE_TF=0` if TensorFlow is installed (a documented hang) |
| Nimble (local) | 3.12 | `torch==2.8.0`, `requirements/training.txt`; separate environments for MLX, PyTorch and curator |

Therefore: **one environment (venv or notebook runtime) per pipeline.** `common/` must work in each. Do not try to install two pipelines in one runtime.

## Kaggle and Colab constraints

Facts below are from general knowledge and must be re-checked in the actual session:

- Free GPUs are typically a T4 (Colab) and T4×2 or P100 (Kaggle). The GPU you get varies by day. **Log the device name in every run.**
- T4 does not have native bf16 (to be verified with `torch.cuda.is_bf16_supported()` and measured speed). Kev's server defaults to bf16 on GPUs; Kev provides `KEV_DTYPE=fp32`. Nimble's README requires a bf16-capable GPU for CUDA.
- Sessions disconnect and quotas run out. Every pipeline must **write results incrementally** (append one line per request and flush) and be **resumable** (skip `query_id`s already present).
- Free-tier RAM and disk limits matter for downloading and merging a 9B model. Check them early (chapter 10).
- Notebooks get the project code and data either from the branch (git clone, needs a token if the repo is private) or, as in the Kev notebook, from a private Kaggle Dataset built with `kev/make_bundle.py` (`dist/kev-bundle/`, git-ignored; rebuild and upload a new Dataset version after any code change). They run, and save logs to persistent storage (Kaggle output / Drive); a run that exists only in a closed session does not exist. Upstream model repos are still cloned from GitHub, pinned to a commit.
- The root `.gitignore` ignores `runs/` in general; `orchestrator-baselines/runs/` is excepted so validated logs can be committed.

## Definition of done per pipeline

1. Smoke test passed on 5 rows.
2. Pilot of 50 validation rows with latency, tokens, memory recorded.
3. Full validation and full test runs complete, logs validated by the shared script.
4. `report.md` and `metrics.json` generated by the shared script.
5. `run.json` complete; notes on anything surprising.
6. Open questions listed in the PR description; no unresolved `PENDING` item silently decided (only X-04 and X-05 remain, both deferred).
